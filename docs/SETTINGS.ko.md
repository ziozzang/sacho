# 설정 메뉴와 자연어 설정 도우미

Copyright Jioh L. Jung <jung@jioh.net>.

[English](SETTINGS.md)

관리자 화면의 **설정 → 서버 설정**에서 파일로 지정하던 항목을 확인하고
바꿀 수 있습니다. 항목·자료형·기본값·설명은 `sacho --help --json`과 같은
설정 스키마에서 자동으로 가져옵니다. 비밀번호와 API 키 자체를 입력하지
마세요. 비밀값은 환경변수명이나 비공개 파일의 경로로 참조합니다.

1. 바꿀 값을 입력합니다. 문자열은 그대로, 숫자·참/거짓·배열은 JSON 형식
   (예: `120`, `true`, `["operator@example.com"]`)으로 입력합니다.
   비어 있는 선택 항목은 제거됩니다. SMTP 같은 선택 표는 필요한 하위
   항목을 모두 채우면 켜지고, **이 설정 제거안** 버튼으로 끌 수 있습니다.
2. **변경안 검증**을 누릅니다. 서버는 `sacho config check`와 같은 설정
   검증기를 사용합니다. 검증된 이전 값과 새 값을 화면에서 비교하세요.
3. **검토한 변경안 승인·적용**을 눌러야 저장됩니다. 변경안은 1시간 뒤
   만료되며, 그 사이 설정 파일이 바뀌면 다시 만들어야 합니다.
4. 감독 프로세스(`sacho serve`)가 변경을 감지해 서버를 다시 시작합니다.
   연결이 잠시 끊길 수 있습니다. 주소나 인증을 바꿨다면 새 주소·계정으로
   다시 접속하세요. `serve --worker`를 직접 실행한 경우 운영자가 재시작해야 합니다.
5. 변경 기록에는 승인한 관리자·시각·이전 값·새 값이 남습니다.
   **이 변경 되돌리기**로 복원할 수 있습니다. 이후 다른 수정이 있으면
   덮어쓰지 않고 거부하므로 새 변경안을 만드세요.

설정 파일과 그 디렉터리에 서비스 계정의 쓰기 권한이 있어야 합니다.
저장할 때 파일을 원자적으로 교체하며 기존 파일 권한은 유지합니다.
TOML 주석과 서식은 보존되지 않습니다. 데이터베이스 경로 변경은 운영 중
허용하지 않습니다. 서비스를 멈추고 별도로 이전하세요. 새 설정으로 서버가
열리지 않으면 감독 프로세스가 이전 설정 파일을 복원합니다. 이 경우 기록의
변경안과 현재 설정을 비교하고, 주소·포트 사용 여부를 확인하세요.
공개 페이지 제목·설명은 위쪽 **공개 페이지** 설정이 우선합니다.

## LLM 연결

서버 설정의 `llm.base_url`, `llm.model`, `llm.api_key_env` 또는
`llm.api_key_file`을 채워 변경안을 승인하세요. 키 참조는 둘 중 하나만
사용합니다. API 주소에는 사용자명·비밀번호·쿼리를 넣을 수 없습니다.
HTTPS를 사용하고, 같은 컴퓨터의 모델 서버에만 루프백 HTTP를 허용합니다.

```toml
[llm]
base_url = "https://api.example.com/v1"
model = "your-model"
api_key_env = "SACHO_LLM_API_KEY"
```

서비스 실행 환경의 `SACHO_LLM_API_KEY`에 키를 공급하거나, `api_key_env`
대신 `api_key_file = "/etc/sacho/llm.key"`를 지정하세요. 키 파일은 소유자만
읽고 쓸 수 있어야 합니다(예: `chmod 600`). 화면에는 키 값 대신
**설정됨/없음**과 참조만 표시합니다. 키를 검사 입력 변수로 허용하지 마세요.
재시작 후 **LLM 연결 시험**으로 모델과 인증을 확인합니다. 이 버튼은 실제
제공자에 요청을 보내므로 사용료가 발생할 수 있습니다. 키 파일의 내용이나
키 환경변수의 값은 API 응답·로그·변경 기록에 넣지 않습니다.

LLM을 설정하지 않거나 `llm` 표를 제거하면 자연어 도우미가 숨겨지며 다른
기능은 계속 동작합니다. 연결 시험은 비활성화됩니다.

## 도우미 사용

목적(서버 / 알림 / 수집 에이전트의 네트워크 검사 / Prometheus·Grafana)을
고른 뒤 「기록을 120일 보관해 줘」처럼 입력하고 **변경안 만들기**를 누르세요.
도우미는 변경안만 만듭니다. 같은 검증·비교·관리자 승인 절차를 거칩니다.
잘못된 제안은 검증 오류를 모델에 돌려 최대 3회까지 고치게 합니다.

수집 에이전트는 먼저 **에이전트** 메뉴에서 등록해야 합니다. 도우미는
등록된 에이전트의 HTTP·TCP·DNS·ping 검사나 Prometheus 수집 검사를
추가할 수 있습니다. CPU·디스크 수집은 기존 node exporter와 Prometheus를
연결하세요. Grafana는 같은 Prometheus를 조회하도록 별도로 설정합니다.
도우미는 Grafana 서버 설정을 직접 바꾸거나 실행 스크립트를 만들지 않습니다.

모델에는 허용된 일반 설정과 사용자의 요청만 보냅니다. 기존 인증·파일
경로·비밀값 참조·검사 코드는 맥락에 넣지 않으며 알려진 비밀값은 가립니다.
요청에 비밀번호·키·민감한 자료를 직접 쓰지 마세요. 인증·키 참조·스크립트·
자동 동작·허용되지 않은 설정 변경은 모델의 JSON 응답에 있어도 거부합니다.
내장 프롬프트 판 번호는 1이며, 설명서와 설정 스키마를 빌드 시 함께 넣습니다.

## 확인 시험

실제 LLM을 호출하지 않는 시험: `python3 tests/settings_wizard.py`.
Chromium 화면 확인 포함: `python3 tests/settings_wizard.py --browser`.
운영 제공자 확인은 선택 사항이며, 연결을 설정한 뒤 **LLM 연결 시험**과
작은 변경안의 생성·취소를 수행하세요. 확인 시험 때문에 설정을 적용할 필요는 없습니다.
