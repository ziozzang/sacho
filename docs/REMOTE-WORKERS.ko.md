# 원격 모니터링 워커

중앙 서버 하나와 여러 원격 워커로 실제 네트워크 위치에서 검사합니다. 같은 실행
파일을 사용하며 중앙은 SQLite를 그대로 쓸 수 있습니다. 워커에는 데이터베이스나
인바운드 포트가 필요 없습니다. 여러 중앙 서버의 HA는 나중 단계로 미룹니다.
장애 관리 업무는 외부 웹훅 수신 시스템에서 처리합니다.

중앙 설정에 워커를 등록합니다. 노드별로 서로 다른 강한 임의 토큰을 만들고 중앙과
해당 워커에 같은 값을 비공개로 주입하세요. TOML에는 값 대신 참조 이름만 씁니다.

```toml
[[remote_workers]]
id = "edge-west"
token_env = "SACHO_EDGE_WEST_TOKEN"
allow_scripts = false
```

환경변수나 암호화 저장소의 `sacho secrets set`으로 토큰을 넣습니다. 토큰은 최소
32바이트 이상의 암호학적 난수로 만들고 Git·명령 인자·로그에 넣지 마세요.
토큰 참조를 `probe_env`에 넣으면 안 됩니다. 등록·교체·삭제 후 중앙을 재시작합니다.
설정에서 노드를 삭제하면 작업 수신과 결과 제출 권한을 함께 철회합니다.

```sh
sacho example remote-worker > worker.toml
sacho worker --config worker.toml
```

워커 설정의 `control_url`, `node_id`, `token_env`를 편집합니다. 토큰 참조 이름은
중앙과 달라도 되지만 값은 같아야 합니다. 검사에 필요한 변수는 워커의 환경 또는
워커 로컬 `[secrets]`로 주입하고 `probe_env`에 허용합니다. 중앙의 변수는 전달하지
않습니다. 공개 인증서가 있는 HTTPS를 기본으로 쓰고, 사설 CA는 `ca_file`로 추가합니다.
로그인 화면을 포함한 HTTP 리다이렉션은 거부합니다. 프록시의 `/api/workers/*`는
Google 로그인으로 보내지 않고 사초의 Bearer 인증에 도달하도록 설정하세요.
`allow_insecure_http=true`는 격리된 테스트에서만 명시적으로 사용할 옵션입니다.

관리자 검사 편집기의 **검사 실행 위치**에 등록된 워커 ID를 넣습니다. 비워두면
중앙에서 실행합니다. **지금 검사**도 지정한 위치에서 실행합니다. 원격 초안
테스트는 아직 지원하지 않아 버튼을 비활성화하고 안내합니다. 로컬에서 테스트하려고
위치를 지웠다면 네트워크와 입력 값이 원격과 다를 수 있다는 점을 고려하세요.

HTTP 검사는 기본 권한으로 실행합니다. Lua·셸·Python은 중앙과 워커 양쪽에서
`allow_scripts=true`가 필요합니다. Lua는 내장되어 있으며 외부 인터프리터와
클라이언트는 워커에 설치해야 합니다. 스크립트는 신뢰한 운영자가 작성하는 권한 있는
코드입니다. 환경변수 허용 목록은 임의 코드에 대한 완전한 격리 장치가 아닙니다.
전용 사용자/컨테이너와 제한된 파일·네트워크·인증정보로 운영하세요.

노드당 동시에 한 작업을 실행하고 대기 중에는 2초마다 요청합니다. 연결 장애 시
최대 30초까지 간격을 늘립니다. 서비스 관리자의 실패 시 재시작을 권장합니다.
SIGTERM은 진행 중인 검사와 하위 프로세스를 취소합니다. 워커 바이너리는 현재
운영자가 갱신하고 재시작해야 하며 자동 감독 업데이트는 중앙 기능입니다.

중앙은 실행 ID·노드·검사 리비전·활성 상태·임대를 확인한 뒤 검사 결과와 상태 변화,
알림 생성을 같은 트랜잭션으로 커밋합니다. 같은 실행의 같은 결과 재전송은 한 번만
기록하고, 다른 결과·오래된 실행·만료·수정·삭제된 검사는 거부합니다. 영수증은 검사별
현재 실행 하나로 제한합니다. 임대는 검사 제한 시간에 30초를 더하며 중앙 시간을
사용합니다. 멈춘 워커가 다시 실행되면 외부 요청 자체는 중복될 수 있으므로 검사는
관측 위주로 작성해야 합니다. 새 알림의 UUID 전달 ID는 재시도·보관 정리·이전 후에도
유지하며 기존 대기 알림의 숫자 ID는 호환성을 유지합니다.

연결이 끊겨 데이터가 오래되면 공개 상태는 기존 신선도 기준에 따라 unknown이 됩니다.
노드 목록의 마지막 결과 시각은 실시간 heartbeat를 보장하지 않습니다. 결과 출력은
요청 크기에 맞게 줄어들 수 있으며 원시 출력은 관리자에게만 공개합니다.

SQLite에는 검사별 `remote_runs`를 추가합니다. 스냅샷 카탈로그 v2는 실행과 결과
영수증을 함께 보존하며 v1 복원은 기존 행을 유지하고 빈 워커 테이블을 추가합니다.
이때 카탈로그 버전이 바뀌므로 정규화한 v2 지문은 원래 v1 지문과 다릅니다.
PostgreSQL 이전도 v2를 지원하지만 실제 중앙 저장소는 아직 SQLite입니다.
DB 전환·복원 전에는 모든 중앙과 워커를 중지하세요.

```sh
cargo test --locked
CC_x86_64_unknown_linux_musl=musl-gcc cargo build --locked --release --target x86_64-unknown-linux-musl
python3 tests/remote_docker.py
python3 tests/storage_docker.py
```

테스트는 격리된 Docker 네트워크·일반 사용자 컨테이너·임시 데이터만 사용합니다.
두 위치의 검사, 워커 입력, 인증/프로토콜 거부, 중복 결과, 멈춘 워커의 작업 인계,
오래된 결과 거부, 연결 복구와 중앙 재시작을 확인합니다. 테스트 시간을 줄이기 위해
격리된 테스트 DB에서만 임대를 단축합니다. 실패 시에도 소유한 컨테이너와 네트워크를
정리합니다. 운영 설정·인증정보와 GitHub Actions를 사용하지 않습니다.
