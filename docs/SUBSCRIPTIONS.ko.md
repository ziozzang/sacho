# 항목과 이벤트를 골라 알림 구독하기

Copyright Jioh L. Jung <jung@jioh.net>.

대시보드의 검사 항목이나 경보 행에서 **구독**을 누르면 해당 항목과 받을 이벤트를 고를 수 있습니다. 관리자는 어느 이메일·웹훅 구독에 넣을지 선택합니다. 일반 방문자는 이메일을 입력하고 받은 확인 메일에서 구독을 확인합니다. 이미 구독한 이메일은 주소만 안다고 바꿀 수 없습니다. 인증 프록시로 로그인하거나 알림 메일 아래의 **구독 규칙 관리** 링크를 이용하세요.

**관리 → 알림 → 구독 선택 규칙**에서 구독별 규칙을 보고 수정·삭제할 수 있습니다. 본인의 확인된 이메일 구독에는 공개 화면에도 **구독 규칙 관리** 버튼이 나타납니다. 규칙마다 개별 검사 항목, 검사 그룹, 이벤트, 최소 심각도와 사용 여부를 정합니다. 규칙끼리는 하나만 맞아도 알림을 받고, 같은 이벤트가 여러 규칙에 맞아도 한 번만 보냅니다.

## 대상과 기존 구독

호스트·서비스·지표는 모두 기존의 검사 항목으로 선택합니다. 묶음은 항목의 검사 그룹(`group`)을 사용합니다. 별도 호스트·태그 목록은 없으며, 검사 그룹은 자료 접근 권한 그룹과 다릅니다. 항목과 그룹은 둘 중 하나가 맞으면 됩니다. 두 목록을 모두 비우면 전체 항목입니다. 그룹에 새 항목을 추가하면 그 그룹 규칙에도 포함됩니다.

규칙을 하나도 만들지 않으면 지금처럼 모든 알림을 받습니다. 기존 구독은 데이터베이스를 열 때 자동으로 빈 규칙으로 이전합니다. **사용 해제**는 규칙을 남겨두고 끄므로 마지막 규칙을 꺼도 전체 수신으로 돌아가지 않습니다. **규칙 삭제**로 모든 규칙을 지우면 전체 수신으로 돌아갑니다. 메일에서 끈 항목·이벤트의 개별 제외 목록은 다른 규칙보다 우선합니다. 제외 목록의 **다시 받기**로 되돌릴 수 있습니다.

## 받을 이벤트

| 이벤트 | 뜻 | 최소 심각도 판정 |
| --- | --- | --- |
| `incident.started` | 연속 실패 기준을 넘어 경보가 시작됨. 수집·검사 실패도 이 경로를 사용합니다. | 주의(`degraded`) 또는 장애(`outage`) |
| `incident.resolved` | 연속 복구 기준을 넘어 경보가 해제됨 | 복구 직전 경보의 심각도 |

최소 심각도는 전체(`info`), 주의 이상(`warning`), 장애만(`critical`)입니다. 이벤트를 고르지 않으면 두 가지 모두 받습니다. 별도의 수집 실패·임의 상태 변화 이벤트는 현재 생성하지 않습니다. 이벤트 로그 패널의 로그는 알림 이벤트 종류를 늘리지 않습니다. 이메일 주소 확인 메일은 규칙과 독립적으로 발송합니다.

복구만 고른 구독은 경보 시작 메일을 받지 않아도 복구 메일을 받습니다. 기존 전체 유지보수·지연·반복 경보 대기 정책은 유지합니다. 두 이벤트를 모두 고른 구독은 시작 경보가 억제되었으면 그 짝인 복구도 억제합니다. 재시도 직전 규칙과 공개 여부를 다시 확인합니다. 공개 이메일에는 제한된 항목을 넣지 않습니다.

## 설정 키 표

아래 설정은 서버 TOML이 아니라 **구독별 데이터베이스 설정**입니다. SQLite·PostgreSQL 간 이동용 백업에 함께 포함됩니다. 백업에는 구독 인증정보와 링크 서명 키도 포함되므로 비공개로 보관하세요.

| 범위 | 키 | 형식 | 기본값 | 뜻 |
| --- | --- | --- | --- | --- |
| 구독 | `rules` | 배열 | `[]` | 하나라도 맞으면 받는 규칙, 최대 64개. 비면 전체 수신 |
| 구독 | `exclusions` | 배열 | `[]` | `{item_id,event}` 개별 제외, 최대 256개 |
| 구독 | `revision` | 문자열 | 서버 관리 | 직접 수정하면 이전 메일의 규칙 해제 링크 무효화 |
| 규칙 | `id` | 문자열 | 필수 | 구독 안에서 고유. 영문·숫자·`_`·`-`, 최대 64자 |
| 규칙 | `item_ids` | 문자열 배열 | `[]` | 개별 검사 항목 ID, 최대 128개 |
| 규칙 | `groups` | 문자열 배열 | `[]` | 검사 그룹 이름, 최대 128개. 항목과 합집합 |
| 규칙 | `events` | 문자열 배열 | `[]` | 위 두 이벤트. 비면 모두 |
| 규칙 | `min_severity` | 문자열 | `info` | `info`, `warning`, `critical` |
| 규칙 | `enabled` | 논리값 | `true` | 삭제 없이 사용 해제 |

```json
{"rules":[{"id":"lab-recovery","item_ids":["ITEM_ID"],"groups":[],"events":["incident.resolved"],"min_severity":"critical","enabled":true}],"exclusions":[]}
```

## API와 명령줄

관리자는 기존 관리자 인증으로 `GET|PUT /api/admin/subscriptions/{email|webhook}/{ID}/rules`를 호출합니다. 구독 ID는 `/api/admin/subscribers`·`/api/admin/webhooks`에서 확인합니다. PUT은 규칙 전체를 교체하며 `X-Sacho-Request: 1` 헤더와 허용된 Origin이 필요합니다.

구독자 본인은 `GET|PUT /api/account/rules`를 씁니다. 확인된 구독자의 프록시 이메일 또는 메일 관리 링크의 토큰을 `Authorization: Bearer TOKEN`으로 전달합니다. PUT에는 위 요청 헤더와 Origin 검사가 적용되며 공개 항목·그룹만 선택할 수 있습니다. 익명 `POST /api/subscribe`는 새 이메일에 `rules` 배열을 함께 받을 수 있고, 기존 이메일 규칙은 바꾸지 않습니다.

```sh
sacho subscriptions schema
sacho subscriptions --database sacho.db list
sacho subscriptions --database sacho.db get --channel email --id SUBSCRIBER_ID
sacho subscriptions --database sacho.db set --channel email --id SUBSCRIBER_ID --input rules.json
sacho subscriptions --database sacho.db set --channel webhook --id WEBHOOK_ID --input rules.json
```

명령줄도 같은 규칙 검증과 저장 방식을 씁니다. 존재하는 SQLite 데이터베이스의 파일 접근 권한이 필요합니다. 한 규칙을 삭제하려면 조회한 JSON에서 해당 줄을 지운 뒤 다시 저장합니다. 끄려면 `enabled:false`, 전체 수신으로 초기화하려면 `{"rules":[]}`를 저장합니다. `subscriptions schema`는 데이터베이스 없이 키와 이벤트를 설명합니다.

## 이메일의 「이 알림만 끄기」

사용자 정의 메일 양식에도 맞는 규칙마다 링크를 추가합니다. 링크를 열면 확인 화면만 표시하고, 버튼을 눌러야 그 규칙을 끕니다. 서명(HMAC-SHA256), 구독·규칙 식별자, 규칙 판, 전송별 식별자, 30일 유효기간을 확인하고 한 번 사용한 링크는 거절합니다. 위조·만료·재사용·수정 전 링크도 거절합니다. 같은 메일에 있는 다른 규칙 링크는 각각 사용할 수 있습니다.

기존 전체 수신 구독은 정확히 해당 항목·이벤트만 제외합니다. 다른 규칙·구독과 전체 구독 해지는 독립적입니다. 관리 링크는 읽은 뒤 브라우저 주소와 방문 이력에서 토큰을 지우며 로컬 저장소에 보관하지 않습니다. 응답에는 기존 캐시 금지와 참조 주소 전달 금지 설정이 적용됩니다.
